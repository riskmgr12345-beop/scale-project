# 저울 (Scale Project)

각 종목이 "오를 이유"(부스터: 거래량비, 최근 빠른반등 이력)와 "내릴 이유"(위험신호: 당일 급반등)를
저울질해서 순점수(-5~+5)로 계산하고, 코스피+코스닥 전체(약 2,700종목) 중 상위 후보를 뽑는
리서치 프로젝트입니다.

## 배경

V3(`stock-autotrading-v3`)의 ZZ 되돌림 전략에서 49종목/8년 데이터로 검증한 "줄다리기" 공식을
그대로 코스피+코스닥 전체에 적용했더니, 방향성(강한이김≥2점이 낫다)은 재현됐지만 절대 수치는
많이 달랐습니다(`scale_validation_result.txt` 참고). 그래서 같은 공식이라도 유니버스가 다르면
별도로 검증·관리해야 한다는 원칙 아래 "저울"이라는 별도 이름/프로젝트로 분리했습니다.

## 데이터 소스

`limitup-precursor-research`(콜라 프로젝트, https://github.com/riskmgr12345-beop/limitup-precursor-research)
가 매주 자동 갱신하는 `research_cache/limitup_ohlcv_cache.pkl`(코스피+코스닥 전체 OHLCV)을
읽기전용으로 재사용합니다. 이 저장소 자체는 시세 데이터를 직접 수집하지 않습니다.

## 파일

- `scale_validation_test.py`: 저울 공식(부스터-위험신호)이 코스피+코스닥 전체에서도 통하는지
  검증한 스크립트 (n=77,750, 강한이김/약한이김/비김/짐 4분류 + 시기분할 재현성 확인).
- `render_scale_report.py`: 상위 15개 종목을 뽑아 보고서(`scale_top15_report.txt`)를 생성하는
  본 프로덕션 스크립트.

## 검증 요약 (2026-09-04)

- 강한이김(≥2점): 5일도달률 72.8%, 5일째평균 +0.49%
- 약한이김(==1점): 65.3% / -1.10%
- 비김(0점): 52.8% / -3.20%
- 짐(<0점): 53.3% / -2.96%
- 시기분할(2025-11-19 기준 전/후반부) 둘 다 강한이김이 우위, 재현됨.

**주의**: "이김"을 넓게(점수>0 전체) 잡으면 평균이 -0.31%로 오히려 마이너스입니다.
반드시 ≥2점(강한이김) 기준으로만 걸러야 합니다.

## 향후 과제

- 종목현황(52주위치는 포함됨, 수급·PER·관리종목 여부는 미포함) 확장 -- 재무/투자자 데이터
  소스 추가 연결 필요.
- 관리종목/거래정지 임박 종목 필터링 검토.
- 클라우드 에이전트로 매일 자동 실행 + 보고. (완료 -- "저울 프로젝트 일일 리포트" 라우틴)
- 생존편향(상장폐지 종목이 캐시에 없음) 미해결 -- 다음 검증 우선순위.

## 데이터 품질 이슈: 거래량 0인 날 (2026-09-04, 사용자가 확대차트 보고 직접 발견)

`엑사이엔씨`의 08-07 하루가 O=H=L=C=760원·거래량=0으로 찍혀있었는데, 전후일(08-06/08-10/08-11)은
전부 3,800원으로 완전히 동일했습니다(거래정지 등으로 실제 거래가 없던 날에 데이터공급사가
임의값을 채워넣은 것으로 추정). 이런 날을 진짜 가격으로 계산하면 지그재그/터치 로직이 가짜
대폭락(-80%)·급반등(+400%) "터치"를 만들어냅니다. `render_scale_report.py`에 `_drop_zero_volume_
days()`를 추가해 거래량<=0인 날을 시계열에서 통째로 제거(그 날 자체가 없었던 것처럼)하도록
고쳤습니다. **주의**: `scale_validation_test.py`(77,750건 백테스트)는 아직 이 필터를 안 씀 --
같은 종류의 가짜 터치가 검증 표본에 섞여있을 가능성이 있어 재검증이 필요합니다.

## 버그: touch_depth_now가 검증 공식과 다르게 계산되던 문제 (2026-09-04, 사용자가 확대차트의
과거 터치 3건 vs 오늘 터치 1건을 직접 비교하다 발견)

과거 터치 마커(`_historical_touch_points`)는 검증 스크립트와 동일하게 "다리 고점 대비 그날
저가"로 depth_pct를 계산하는데, 오늘(라이브)의 depth_pct를 만드는 `touch_depth_now`는
`(오늘 종가/오늘 저가-1)*100`(오늘 하루의 자체 반등폭)으로 **전혀 다른 공식**을 쓰고 있었습니다
-- 상위 20개 필터링·순위에 실제로 쓰이는 값이 검증된 정의와 안 맞았던 진짜 버그입니다. 예:
로체시스템즈 09-03 -- 버그 있던 값 2.5%p(오늘 반등폭) vs 올바른 값 6.83%p(다리 고점 6,880원
대비). `pos["leg_start_price"]`(다리 시작 고점) 기준으로 고쳐서 `_historical_touch_points`와
공식을 통일했습니다. 고친 뒤 전체 후보군이 537종목→1,712종목으로 크게 늘었고(진짜 깊은
되돌림이 더 정확히 잡힘) 상위 20개 순위도 전면 교체됐습니다. **`scale_validation_test.py`
자체는 처음부터 올바른 공식을 썼으므로 검증 수치(72.8%/+0.49% 등)는 영향 없음** -- 이번
버그는 라이브 리포트(`render_scale_report.py`)에만 있었습니다.

## 강한이김(≥2점) 안에서 확률을 더 올리는 방법 검증 (2026-09-04)

강한이김(≥2점, n=16,127~77,750) 모집단 안에서 확률을 더 높일 방법 3가지를 검증했습니다.
방법론은 동일: 최소표본 15건, 시기분할(전/후반부) 재현성, 도달률뿐 아니라 실제수익률.

**① 시장국면(코스피 60일선) 필터 -- 채택, 프로덕션 반영 완료.** 코스피 종가가 자기 60일
이동평균 위(상승장)/아래(하락장)냐로 나눠보니:
- 상승장: 강한이김 5일도달률 69.7%, 평균 -0.26%
- 하락장: 강한이김 5일도달률 **79.3%**, 평균 **+2.06%**

반직관적이지만(시장 전체가 눌려있을 때 개별종목 반등신호가 더 잘 맞음), 시기분할 둘 다 같은
방향으로 재현됨(`regime_filter_result.txt`/`regime_timesplit_result.txt`). 국면 데이터는
`build_kospi_regime_cache.py`가 GHA로 매일 미리 조회해 `research_cache/kospi_regime_cache.json`
에 캐시하고(클라우드 라우틴 네트워크 제약 우회), `render_scale_report.py`가 화면 상단에
배지로 표시합니다.

**② 유동성(진입 직전 20일 평균거래대금) 필터 -- 기각.** 3분위로 나눠도 유동성 낮은 쪽이
오히려 근소 우위(74.1% vs 72.0%)였고, 거래대금 하한선을 1억→30억원까지 올려도 거의 안
움직였습니다(71.9~72.9%). 시기분할하면 방향이 아예 뒤집혀서(전반부: 하위1/3이 우위 /
후반부: 거의 동률) 재현 안 됨으로 결론. "저유동성 소형주가 노이즈 원인"이라는 가설은 이
방식으로는 뒷받침되지 않았습니다.

**③ 되돌림깊이(depth_pct) 구간별 세분화 -- 기각(근거 약함).** 7~10%p(73.3%) / 10~15%p(71.5%)
/ 15~20%p(75.5%, n=417) / 20~30%p(63.6%, n=151) / 30%p+(70.8%, n=24)로, "깊을수록 좋다"는
단조 패턴이 아니었습니다. 특히 30%p+의 평균수익 +35.96%는 표본 24건 중 극단값 1~2개에
좌우된 것으로 보여 신뢰 불가. 얕음(7~10%p) vs 깊음(20%p+)의 시기분할도 완전히 뒤집힘
(전반부 -3.55% vs 후반부 +10.04%) -- 재현 안 됨.

검증 스크립트: `liquidity_depth_test.py` (`liquidity_depth_result.txt`에 전체 결과),
`regime_filter_test.py` (`regime_filter_result.txt`/`regime_timesplit_result.txt`).
